# 实机验收清单

## 自动检查

- 状态规范化、16 路上限、默认静音、账号与设备稳定 alias。
- 日志字段脱敏、30 天保留边界、脱敏 ZIP 导出。
- 认证网关拒绝无 cookie、错误 Origin、未知 alias、路径穿越和超过 16 路的连接。
- 真正引擎启动、认证 HTTP、内存配置和加密会话持久化。
- UI 的密码/验证码流程、布局恢复、单格声音、管理画面、设置及退出登录（模拟小米接口）。
- Go H.265 和 TUTK 的已有回归测试。
- 客户端相同版本的 Electron 与自带引擎、FFmpeg：16 路独立合成 H.264/Opus 画面逐路解码、仅音频协商时自动切换兼容源、兼容转码、声音开关及重连。使用含空格的安装路径，不依赖外部浏览器。

## Windows 实机验收（主机已上线）

1. 核对原 go2rtc 版本/源码及配置，仅导入小米会话，不替换现有任务；原进程可保留，测试时避免同台摄像头的多重连接竞争。
2. 安装客户端，确认不需要另装 Node、Go、浏览器、WebView2 或 FFmpeg。
3. 导入现有会话，确认自动发现、自动播放；重启电脑后缓存仍有效。
4. 用一台真实摄像头依次验证高清、流畅、兼容、声音、连接中断恢复；观察实际画面及音频。
5. 开始测试最多 16 个真实视频消费者，确认所有可见画面有新帧、隐藏格数不占连接；测 CPU、内存和长期稳定性。UI 显示 16 个格子不等于验证 16 路真实解码。
6. 验证关闭记住声音后重启静音，开启后逐格恢复；反复点击声音开关。
7. 设置开机自启及自动全屏，退出系统账户再登录，确认单实例且只启动客户端拥有的引擎。
8. 强制中止引擎，确认自动恢复；退出客户端确认引擎和 FFmpeg 子进程退出。
9. 导出日志，在私有环境检查无账号、DID、MAC、设备名称、IP、token、完整 URL 及密码；原始加密缓存不能发送给维护者。

## macOS

Apple 芯片和 Intel 各做一次上述实际小米摄像头测试；验证 Keychain 访问、DMG 安装、登录项开关、全屏、声音及退出时资源释放。开发机的模拟 UI 和引擎启动不代替这些实机验收。

## 网络边界

- 本地回归：真实 CS2/TUTK 握手对无响应 UDP 设备应超时返回，不得到视频连接；界面连接错误后提示重连，保留账号和布局。
- 实机待验：电脑连接摄像头所在 LAN，确认新帧；切换到不通该 LAN 的手机热点（无 VPN/子网路由），即使账号和列表可用也应无法播放；返回 LAN 后确认重连恢复。
- 再分别检查访客隔离、摄像头断电、IP 变化及云端取密钥失败。失败本身无法区分这些原因，不能显示为精确的“非局域网”诊断。
